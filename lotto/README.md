# 로또 6/45 분석·예측·백테스트 (`lotto/`)

1회(2002-12-07)부터 최신 회차까지의 당첨번호를 수집해 상세 분석하고, 여러 "예측 전략"으로
다음 회차 번호를 생성한 뒤, **워크포워드 백테스트**로 "n회까지 분석 → n+1회 예측 → 실제와 비교 →
왜 틀렸는지 진단"을 전 회차에 대해 자동으로 수행합니다.

> **먼저 알아야 할 결론.** 로또 추첨은 매 회차 독립적인 무작위 추출이라 과거 번호에는 다음 회차에
> 대한 정보가 없습니다. 이 프로그램의 분석(균등성 검정, 재출현률, 핫넘버 지속성, 자기상관)과
> 백테스트(1,246회차 × 8전략)는 모두 그 사실을 확인합니다. 어떤 전략으로 고르든 한 게임의 1등 확률은
> 1/8,145,060이며, 기대 적중 수는 게임당 0.8개입니다. 이 도구는 "예측이 왜 안 되는지"를 데이터로
> 보여 주는 도구이지, 당첨 확률을 올려 주는 도구가 아닙니다. 복권 구매는 여유 자금 안에서만 하세요.

## 설치와 실행

```bash
cd lotto
pip install -r requirements.txt      # numpy, scipy
python -m lotto645 update            # 데이터 최신화 (동행복권 API → 실패 시 GitHub 미러)
python -m lotto645 analyze --out reports/analysis.md
python -m lotto645 predict           # 다음 회차 예측 (8전략 × 5게임)
python -m lotto645 explain 2         # 1회 분석 → 2회 예측 → 실제와 비교, 왜 틀렸는지
python -m lotto645 backtest          # 2회~최신회 전체 백테스트 + reports/ 저장
python -m unittest discover -s tests # 테스트
```

네트워크가 없으면 `--offline`을 붙이면 `data/lotto645.csv`(저장된 데이터)만 사용합니다.
`--until N`을 붙이면 N회까지의 데이터만 있는 과거 시점을 재현합니다
(예: `python -m lotto645 --until 1000 predict` 는 1001회 예측).

## 데이터

- `data/lotto645.csv`: 회차, 추첨일, 번호 6개, 보너스, 1등 당첨금/당첨자 수, 총 판매액.
- 수집 순서: 로컬 CSV → 동행복권 공식 API(`common.do?method=getLottoNumber`) → GitHub 공개 미러
  (`smok95/lotto`, 공식 API가 막힌 네트워크용). 저장 시 1회부터 빠진 회차가 없는지 검증합니다.

## 분석 항목 (`analyze`)

| 구분 | 내용 | 판정 방법 |
|---|---|---|
| 번호 빈도 | 1~45 출현 횟수, 보너스 빈도, 핫/콜드 10개, z값 | 카이제곱 균등성 검정 |
| 미출현 | 번호별 현재 미출현 기간, 역대 최장 미출현 | 표 |
| 조합 패턴 | 합계(평균·백분위), 홀짝, 고저, 연번, AC값, 구간 사용 수, 끝수 | 이론 분포(초기하)와 비교 |
| **예측 가능성** | 직전 회차 번호 재출현률, 핫넘버/콜드넘버의 다음 회차 적중률, 시차 1~5 자기상관, 동반출현 쌍 | 이항검정, 기대치 비교 |
| 당첨/판매 | 1등 당첨자 수·당첨금·판매액 요약 | 표 |

결과 예(1~1247회): 균등성 p=0.963, 재출현률 13.8% vs 기대 13.3%(p=0.26),
핫넘버 다음 회차 적중률 13.5% vs 기대 13.3%(p=0.68). 전부 무작위와 구별되지 않습니다.

## 예측 전략 (`predict`)

| 이름 | 가정 | 점수 |
|---|---|---|
| `frequency` | 자주 나온 번호가 계속 나온다 | 누적 출현 횟수 |
| `cold` | 오래 안 나온 번호가 곧 나온다 | 미출현 기간 |
| `recent` | 최근 흐름이 이어진다 | 최근 20회 지수가중 빈도 |
| `markov` | 직전 회차 번호 뒤에 따라오던 번호가 또 온다 | 1차 전이확률 합 |
| `pair` | 함께 자주 나온 번호가 함께 나온다 | 빈도 + 동반출현 친화도 |
| `ensemble` | 신호를 합치면 안정적이다 | 위 4개 표준화 평균 |
| `unpopular` | 적중은 같지만 남이 덜 고르는 번호면 당첨금 몫이 크다 | 1등 당첨자 수 회귀로 추정한 인기도의 음수 |
| `balanced` | 번호엔 정보가 없지만 '전형적 모양'이 유리하다 | 균등 + 패턴 필터 |
| `random` | 아무 가정 없음 (**기준선**) | 균등 |

점수 상위 15개(풀)에서 점수 가중 추출로 서로 다른 5게임을 만듭니다. 패턴 필터(합계 90~186,
홀수 1~5, 저구간 1~5, 연번 ≤2쌍, 같은 끝수 ≤3개)는 실제 당첨 조합의 약 84%가 통과하는 범위입니다.
시드가 회차·전략에 고정되어 같은 입력이면 항상 같은 조합이 나옵니다(백테스트 재현성).

## 백테스트와 오답 진단 (`backtest`, `explain`)

회차 n마다 **1~(n-1)회 데이터만으로** 점수를 계산하고 조합을 만들어 실제 n회와 비교합니다.
회차별로 다음을 기록·설명합니다.

1. 게임별 적중 수, 등수, 최고/평균 적중 (무작위 기대 0.8개/게임)
2. 실제 당첨번호 6개가 모델 순위에서 몇 위였는지 (정보가 없으면 평균 23위)
3. 상위 K개 풀에 실제 번호가 몇 개 들어왔는지 (무작위 기대 6K/45)
4. 전략의 가정 검증: 실제 번호의 과거 빈도·미출현·최근 출현·직전 회차 겹침이 가정과 맞았는지
5. 패턴 필터가 실제 당첨 조합을 배제했는지, 어떤 조건 때문인지
6. 결론 문장 ("왜 틀렸는가")

전략별 집계는 회차 간 독립성을 이용해 **회차 평균 적중**을 표본으로 기대치 0.8과 t검정하고,
`random` 기준선과 대응표본 t검정으로 비교합니다. 같은 회차의 5게임은 같은 풀에서 나와 서로
상관되므로 게임 단위로 검정하지 않습니다.

생성 파일 (`reports/`):

- `analysis.md`, `analysis.json`: 상세 분석
- `backtest_summary.md`: 전략별 성적표, 적중 분포, 판정, 예시 회차(2, 3, 100, 500, 1000, 1247회)의 상세 진단
- `backtest_summary.json`: 집계 수치
- `backtest_rounds.csv`: 전 회차 × 전략별 예측 조합, 적중, 순위, 진단 문장

## 후보군 방식 (`pool`, `pool-backtest`)

"45개 중 분석으로 핵심 후보 15개 → 비후보군 30개에서 3개 추가 → 최종 후보 18개 → 예측 6개" 흐름을
회차마다 수행하고, 핵심/추가/통합 후보 각각의 적중 수와 예측 6개의 적중, 그리고 **후보 밖에서 나온
번호가 왜 밀렸는지**(모델 순위·누적 빈도·미출현·최근 출현)를 회차별로 저장합니다.

```bash
python -m lotto645 pool                                   # 다음 회차 후보 18개 + 예측 6개
python -m lotto645 pool --round 1247                      # 1246회까지 분석 → 1247회 복기
python -m lotto645 pool-backtest                          # 2~최신회 전 구간 (기본: ensemble 핵심, cold 추가, 1게임)
python -m lotto645 pool-backtest --strategy frequency --wild-rule pair --core 15 --wild 3 --games 5
```

옵션: `--strategy` 핵심 후보 선별 전략(점수형 6개), `--core` 핵심 수, `--wild` 추가 수,
`--wild-rule` 추가 후보 규칙(`cold` 가장 오래 안 나온 번호, `recent` 최근 가중 출현, `pair` 핵심 후보와 동반 출현,
`random`), `--games` 예측 게임 수.

결과(2~1247회, 1,246회차):

| 설정 | 핵심 15개 적중 (기대 2.00) | 통합 18개 적중 (기대 2.40) | 예측 6개 적중/게임 (기대 0.80) |
|---|---|---|---|
| ensemble + cold | 1.94 | 2.34 | 0.774 |
| frequency + cold | 1.96 | 2.36 | 0.785 |
| recent + pair | 2.01 | 2.39 | 0.811 |

후보 밖에서 나온 번호의 모델 순위는 후보 밖 구간(16~45위)에 고르게 퍼져 있어, 모델이 그 번호를 낮게 본
이유가 다음 추첨과 무관했음을 보여 줍니다. 산출물은 `reports/pool_summary_<설정>.md|json`,
`reports/pool_rounds_<설정>.csv`(회차별 후보·적중·틀린 번호·진단, git 제외).

## 적중률 "향상"에 대해 — 업그레이드 4종과 검증 결과

적중 확률(게임당 기대 0.8개, 1등 1/8,145,060)은 어떤 선택 규칙으로도 바뀌지 않습니다. 그래서 이
프로그램의 업그레이드는 "확률을 올리는 척"이 아니라, **실제로 바뀌는 것**만 다룹니다.

| 업그레이드 | 명령 | 바뀌는 것 | 바뀌지 않는 것 | 1,246회차 검증 |
|---|---|---|---|---|
| 비인기 번호 전략 | `predict --strategy unpopular`, `popularity` | 당첨 시 공동 당첨자 수(= 받는 금액) | 적중 확률 | 적중 0.796/게임(무작위와 동일), 모델이 '비인기'로 본 조합의 실제 1등 공동 당첨자 13% 적음(미래 검증, p=0.008) |
| 커버리지 생성 | `predict --coverage`, `backtest --coverage` | '전부 꽝' 회차 비율, 적중 분산 | 평균 적중 | 전부 꽝: 무작위 1.4%→0.0%, 풀 전략 15%→7%; 평균 적중 변화 없음 |
| 학습/검증 분할 + 본페로니 | `backtest --split 700` | 우연을 효과로 착각하는 실수 | - | 9개 전략 중 두 구간에서 재현된 것 없음 |
| 후보군 방식 | `pool`, `pool-backtest` | 후보 18개 안에 들어온 개수 추적, 틀린 번호 저장 | 18개 적중 기대 2.4개 | 2.34~2.39개(무정보와 동일) |

**인기도 모델**(`popularity.py`)은 100회 이후 회차의 "1등 당첨자 수 / 판매 게임 수"를 번호 지표 45개로
릿지 회귀해 번호별 인기도를 추정합니다. 덜 인기: 42, 41, 15, 30, 21, 22… / 인기: 12, 5, 8, 10, 7, 17…
(생일·행운 숫자 쪽이 인기). 효과 크기가 작은 이유는 한국 로또의 자동 구매 비중이 높기 때문입니다.
`reports/popularity.md`에 상세.

**바꾸지 말아야 할 것**: 패턴 필터는 실제 당첨 조합의 16%를 처음부터 배제하면서 남긴 조합의 확률은
올리지 못합니다. 적중만 생각하면 `--strategy random`(필터 없음)이 가장 손해가 없습니다.
